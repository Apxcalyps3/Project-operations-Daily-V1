# OPERATIONS DAILY – PROJECT SPECIFICATIONS

## 1. VISUAL IDENTITY & GLOBAL UI
- Theme: High-Contrast Retro Green / Cyberpunk.
- Color Palette: Neon Green (#4ade80), Deep Green (#14532d), True Black (#000000).
- Centering Logic: Every page MUST be perfectly centered horizontally and vertically in the viewport. If Tailwind flex/grid fails, use standard CSS: { display: flex; justify-content: center; align-items: center; min-height: 100vh; }.
- Background: Apply 'src/assets/bg-grid.png' to a fixed perspective container. The grid should look like a floor receding into the distance (3D transform).
- Header: The 'logo-main.png' stays at the top of every page. It is a functional Home Link to '/'.

## 2. NAVIGATION & FLOWCHART LOGIC
- Home Page (/): 4 horizontal window buttons (Solver, Challenge, History, Settings).
- Solver Selection (/solver): 2 horizontal buttons (LP Solver, IP Solver).
- LP Solver (/solver/lp): Simplex interface. 
- IP Solver (/solver/ip): Integer programming interface.
- History Selection (/history): 2 horizontal buttons (Solver History, Challenge History).
- Settings (/settings): 3 horizontal buttons (Account, Theme, Review).
- Back Buttons: Every sub-page must have a '< BACK' button that returns to the previous hub in the flowchart.

## 3. SOLVER FUNCTIONAL SPECS
### A. Input Logic
- Variable Control: '+' and '-' buttons to set number of variables (2-4). UI must dynamically add/remove input boxes for the Objective Function (Z) and all Constraint rows.
- Subjective Constraints: Users can add/remove functional constraints. Each row needs a 'Trash' icon to delete.
- Structural Constraints (Hardcoded & Visible):
    * Non-Negativity: 'Xn >= 0' must be automatically displayed at the bottom of the list.
    * Integer Rule: For IP models, 'Xn ∈ ℤ' must be displayed.
### B. Method Selection
- LP Solver: Options = DUAL SIMPLEX, BIG M, PRIMAL-DUAL. (Do not limit by Max/Min).
- IP Solver: Options = CUTTING PLANE, BRANCH & BOUND.

## 4. MATH ENGINE & OUTPUT (EMATHHELP / ATOZMATH STYLE)
- Step-by-Step Tableaus: The solver must return an array of steps. Users use 'Next/Prev' buttons to flip through them.
- Tableau Detail: Each step must show a full matrix including Basis, Variables, RHS, and Ratios. Highlight the pivot row/column.
- Row Operations: For every iteration, display the exact formula used, e.g., 'R2(new) = R2(old) - (value) * R1(pivot)'.
- Explanations: Provide text for each step identifying entering/leaving variables and the reason for the current pivot.

## 5. GRAPHICAL VISUALIZATION (2D ONLY)
- Match: If variables = 2, show a graph.
- Aesthetic: Monochromatic Green theme.
- Interactive: Must be zoomable (scroll) and draggable (pan).
- Region: Shade the 'Feasible Region' with a semi-transparent green glow. Mark the Optimal Point clearly.

## 6. DAILY CHALLENGE ENGINE
- Seeded Randomization: Generate one unique problem every 24 hours using the date (YYYY-MM-DD) as the random seed.
- Problem Mix: Randomly select 2-4 variables and 2-4 subjective constraints.
- UI Bracket: The curly bracket '{' must scale to fit all functional and structural constraints.
- Timer: A real-time countdown to the next local Midnight (IRL time).
- Verification: Submit button compares user input to optimal math result. Return: 'Optimal', 'Feasible but not Optimal', or 'Infeasible'.
